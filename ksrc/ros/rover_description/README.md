## 링크와 좌표

`base_link`는 좌우 로커 회전축의 중앙이며 X 전방, Y 왼쪽, Z 위입니다.
Fusion CAD의 +Y가 전방입니다. CAD 글로벌 원점에 대한 `base_link` 위치는
`(0, 0, 161.813) mm`입니다.

CAD 좌표 `(X,Y,Z)` mm를 base_link 좌표로 바꾸면 `(Y,-X,Z-161.813)` mm입니다.

| 관절 | 부모 → 자식 | 로컬 축 |
|---|---|---|
| `left_rocker_joint` | 차체 → 왼쪽 로커 | `0 1 0` |
| `right_rocker_joint` | 차체 → 오른쪽 로커 | `0 1 0` |
| `{fl,fr,rl,rr}_steering_joint` | 로커 → 허브·구동 모터 | `0 0 1` |
| `{fl,fr,rl,rr}_wheel_joint` | 허브·구동 모터 → 휠 | `0 0 1` |

휠 관절 프레임의 회전으로 로컬 Z축을 실제 수평 휠 축에 맞췄습니다.
모든 휠의 양의 회전은 전진 방향입니다.
조향 모듈은 로커의 자식이므로 로커가 기울 때 조향축도 함께 기울어집니다.

### 스월브 기구학의 조향축 간격

로커 0 자세의 앞뒤 조향축 간격은 **204.862785 mm**, 좌우 간격은 **265.000 mm**입니다.
기구학에는 차체 외곽 폭이 아니라 아래 조향 피벗의 좌표를 사용합니다.
기준점은 `base_link`, X는 전방, Y는 왼쪽이며 단위는 m입니다.

| 모듈 | X | Y | Z |
|---|---:|---:|---:|
| FL 앞왼쪽 | +0.102431393 | +0.132500000 | -0.045313244 |
| FR 앞오른쪽 | +0.102431393 | -0.132500000 | -0.045313244 |
| RL 뒤왼쪽 | -0.102431393 | +0.132500000 | -0.045313244 |
| RR 뒤오른쪽 | -0.102431393 | -0.132500000 | -0.045313244 |

조향축은 서보 출력축–휠 허브 연결점이며, 그 수직 아래 구동축까지의 거리는
**69.000 mm**입니다. 구동축 기준점의 X/Y는 위 표와 같고 Z는 **-0.114313240 m**입니다.
기존 URDF `wheel_joint` 원점은 축 방향으로 바깥쪽 9.530 mm 이동한 점입니다.
두 점은 같은 구동 회전축 위에 있습니다. 두 좌표는 `config/swerve_geometry.json`과
`docs/joint_centers.md`에 함께 기록했습니다.

차체 속도 `(vx,vy)`와 yaw 각속도 `wz`에 대한 모듈 i의 평면 속도는
`vix = vx - wz*yi`, `viy = vy + wz*xi`입니다. 조향각은 `atan2(viy,vix)`,
휠 선속도는 `hypot(vix,viy)`로 계산합니다. 위 좌표는 전체 조립 좌표이며,
URDF의 조향 joint origin에 있는 로커 기준 로컬 좌표와 구분해야 합니다.
로커가 기울면 피벗 위치와 조향축 방향도 변하므로 3D 계산에서는 현재 관절각의
순기구학을 사용합니다. 고정 XY 좌표는 로커 수평 자세의 평면 근사입니다.

URDF에는 `q_right=-q_left` mimic 관계를 넣었습니다. MuJoCo MJCF에는 별도의
joint equality를 넣었으며 로커에 위치 제어 액추에이터를 달지 않았습니다.
내부 관절 10개 중 독립 자유도는 9개이며 조향·구동 8개만 능동 제어합니다.
고정 센서 프레임까지 포함하면 링크 22개, 관절 21개입니다.

## 센서

이번 F3Z 안의 IMU와 D435 부품은 제외했습니다. 별도로 받은 STL과 사용자가 지정한
원점을 사용하며 기존 CAD 센서의 회전·배치는 가져오지 않았습니다.

| 대상 | CAD 글로벌 STL 원점 (mm) | base_link 원점 (m) | 질량 |
|---|---|---|---:|
| D435 `camera_link` | `(0,116.619,157.691)` | `(0.116619,0,-0.004122)` | 72 g |
| IMU `imu_link` | `(0,0,137.213)` | `(0,0,-0.024600)` | 2.4 g |

IMU의 마지막 위치 수정인 Z축 -2.4 mm를 반영했습니다. IMU STL의 원점을 보존하고
native STL 축이 CAD 축과 같도록 배치했습니다. `imu_sensor_frame`은 현재 STL 원점과
같습니다. 실제 센서 칩 위치와 축 방향의 보정은 아직 실측하지 않았습니다.

D435는 +CAD Y 방향에서 수평보다 **35도 아래**를 바라보게 배치했습니다.
기존 STL 원점을 유지하고 `camera_link_joint`에 ROS Y축 +35도
(`rpy = 0 0.6108652381980153 0`)를 적용합니다. 카메라 메시, 충돌 형상,
관성 및 좌우 광학 프레임이 모두 함께 회전합니다. 사용자의 별도 STL은 폭 X,
높이 Y, 전면 +Z인 모델로 취급하고, 공식 모델의 메시 회전
`rpy=(pi/2,0,pi/2)`를 적용해 ROS 좌표에 맞췄습니다.

두 스테레오 카메라는 중앙 기준 좌우 25 mm, 간격 50 mm입니다.
전면판과 nominal zero-depth plane 사이의 4.3 mm는 전방 방향의 별도 오프셋입니다.

| 광학 프레임 | CAD 글로벌 원점 (mm) |
|---|---|
| `camera_infra1_optical_frame` — 왼쪽 | `(-25,113.096646,160.157379)` |
| `camera_infra2_optical_frame` — 오른쪽 | `(25,113.096646,160.157379)` |
| `camera_stereo_center_optical_frame` | `(0,113.096646,160.157379)` |

`camera_depth_optical_frame`은 공식 구성처럼 왼쪽 카메라 기준입니다.
광학 축은 X 오른쪽, Y 아래, Z 전방입니다. `camera_link`는 중앙 STL 원점이므로
공식 모델의 왼쪽 IR 기준 `camera_link`와 의미가 다릅니다.

D435의 좌우 영상은 흑백 센서 영상이며 RGB 카메라 두 개가 아닙니다.
패턴 프로젝터를 끄는 패시브 스테레오 구성을 전제로 했습니다.
URDF가 실제 장치의 emitter 설정을 바꾸지는 않습니다.
실기에서는 보정된 intrinsics/extrinsics를 우선하고 동일 이름의 TF를 중복 발행하지
않도록 URDF와 카메라 드라이버의 프레임 발행을 조정해야 합니다.

MuJoCo에 좌우 카메라 두 개와 IMU accelerometer/gyro를 넣었습니다.
시뮬레이터 카메라의 fovy=58도는 nominal 근사이며 실제 해상도·내부 파라미터를
보정한 값이 아닙니다. 스테레오 매칭이나 실제 깊이의 결측·노이즈 모델은 별도 작업입니다.

프레임 참고: https://github.com/realsenseai/realsense-ros/blob/ros2-master/realsense2_description/urdf/_d435.urdf.xacro

## 전장부와 질량

새 CAD의 조립 변환과 참조 부품을 추출했습니다. 배터리·보드·드라이버는 모두 차체에
고정된 하나의 강체로 합산했습니다. 조향 드라이버의 대체 모델은 따로 배치된
MDD3A occurrence 6734입니다. 두 구동 드라이버는 occurrence 5293과 5516입니다.

| 강체 묶음 | 질량 | 수량 |
|---|---:|---:|
| 차체 + 고정 전장 + 라지기어 | 791.9 g | 1 |
| 로커 + 서보 몸체 2개 + 스몰기어 | 186.2 g | 2 |
| 조향 허브 + 구동 모터 | 224.8 g | 4 |
| 휠 | 47.1 g | 4 |
| D435 | 72 g | 1 |
| IMU | 2.4 g | 1 |

몸체 408.5 g은 `773.1-15.6-349`이며 349 g은 이전 전장부입니다.
현재 전장부를 따로 합산하여 중복을 피했습니다.
조향 드라이버는 MDD3A 형상을 쓰면서 질량은 실측 12.9 g을 적용했습니다.
구동 MDD3A는 각각 20 g입니다. 라즈베리파이+AI HAT의 합산 질량 71.2 g은
라즈베리파이 모델에 모았으며 AI HAT의 별도 무게중심은 미측정입니다.

STM 보드는 F411RE CAD 대체 모델과 조립 변환을 사용합니다. 해당 F3D에는 표시용
삼각형 메시가 없어 MB1136의 70×82.5 mm 외형을 상자로 단순화했고, 원점 정렬과
20 mm 높이는 CAD mating origin을 이용한 근사입니다. 실제 MCU는 사용자의 F446RE입니다.
기준 치수: https://www.st.com/resource/en/user_manual/DM00105823.pdf

질량은 실측값입니다. 제공된 CAD/센서 형상 **28개를 부품별 STL로 분리**하고,
닫힌 부피의 무게중심·관성을 계산했습니다. `유효 밀도 = 실측 질량 / STL 부피`로
부품별 내부 균일 밀도를 적용합니다. 모든 부품에 같은 밀도를 넣은 것은 아니며,
전자부품·모터·센서 내부의 서로 다른 재료 분포는 의도적으로 무시합니다.
메시 28개의 폐곡면·일관된 면 방향·양의 부피를 확인했고, 실측 질량에 맞춘
부품 관성 텐서를 평행축 정리로 각 강체 링크에 합산했습니다.
질량은 g를 1000으로 나눈 kg, 길이는 m, 관성은 kg·m²입니다.
예를 들어 D435 72 g은 `<mass value="0.072"/>`입니다.

- 원본에서 이미 하나의 닫힌 입체인 15개는 그대로 사용했습니다.
- 나머지 13개는 분리된 입체의 합집합, 작은 구멍 보정, 기록된 내부 빈 공간 차감으로
  준비했습니다. 겹친 부피는 중복 합산하지 않습니다.
- 배터리·Pi·카메라·IMU의 일부 열린 셸은 볼록 형상으로 근사했습니다. 해당 셸 수,
  폐기한 평면 표시 조각, 보정 내역은 `mesh_preparation_audit.json`에 기록합니다.
- 일부 접촉 면의 겹친 정점은 STL 저장/재로드에서 비정상 연결을 만들기 때문에
  최대 0.000163 mm 분리했습니다. 부피·무게중심 변화가 수치 허용치 이내인지 확인했습니다.
- STM은 기존 상자 대체 모델을 STL로 저장해 계산한 것입니다. 실제 보드의 정밀
  STL로 바뀐 것은 아닙니다. Pi+AI HAT 질량도 여전히 Pi 대체 형상에 모았습니다.
- 실제 형상이 제공되지 않은 기어 3개는 기존 집중 질량·관성 근사를 유지합니다.

별도 관성용 STL은 `meshes/inertial_parts`에 포함합니다. CAD 부품 26개의 삼각형
추출 범위와 좌표 변환을 원본과 비교했고, 대응 좌표의 최대 오차는 30 nm 미만입니다.
원본 시각화 메시를 보존하고 `components.json`의 부품별 삼각형 범위로 재추출합니다.
관성 계산용 메시를 보정해도 시각화 메시와 충돌 형상은 바꾸지 않습니다.
구조물은 외곽 상자가 아닌 실제 벽·바닥·구멍 형상이 계산에 들어가지만, FDM의 인필과
외벽 간 밀도 차이는 STL에 없어 근사입니다. 유효 밀도는 PLA의 재료 밀도가 아닙니다.
URDF의 각 `inertial/origin`은 해당 링크의 로컬 무게중심이며, 전체 무게중심은
각 링크의 위치·자세를 적용한 질량 가중 평균입니다. 재생성 스크립트는
현재 카메라 자세까지 적용해 `cad_reference.json`을 자동 갱신합니다.
MuJoCo에는 질량과 관성을 명시하고 `inertiafromgeom="false"`로 설정하여
기본 밀도로 이 값들을 다시 추정하지 않도록 했습니다.
스몰기어는 각 로커 피벗, 라지기어는 차체의 로커축 중앙에 질량을 배분했습니다.
기어의 정확한 강체 소속·관성은 생략된 실제 기어 구조를 확인하면 개선할 수 있습니다.

## 검증 결과와 남은 조정

자동 검사 16개가 통과했습니다. 질량·관성·센서 자세·스테레오 프레임·부품 STL,
중첩 부피 합집합과 STL 저장/재로드를 검사합니다.
MuJoCo 3.14.0에서 다음을 실제 실행했습니다.

- 자유롭게 움직이는 차체, 능동 액추에이터 8개, 수동 로커 equality 1개로 모델 로드.
- 평지 정착 후 4륜 +2 rad/s 명령으로 1.5초 동안 약 0.141 m 전진.
- 왼쪽 로커에 외부 토크를 주었을 때 좌우가 같은 크기로 반대로 움직임.
- 왼쪽 앞 바퀴 아래 15 mm 단차에 정착하면서 로커가 반대 방향으로 기울어짐.
- 마찰계수 1.0인 강체 30도 경사에서 같은 명령으로 1.5초 동안 약 0.065 m 상승.
- 수치 경고 없음. 좌우 로커 각도 합의 최대 오차는 약 0.00039 rad 이하.

이 결과는 **설정한 강체 지면과 추정 액추에이터 조건의 기본 검증**입니다.
실제 모래의 30도 등판 성능을 입증하지 않습니다.
초기 충돌 형상은 부품별 상자와 러그 최대 반경을 포함한 휠 원통이며
MJCF에서는 로봇 내부 충돌을 껐습니다. 로봇–지면 접촉은 활성화되어 있습니다.

현재 부품별 균일 밀도 모델의 무게중심은 CAD 기준 `(-0.320,5.487,94.706) mm`입니다.
`base_link` 기준 ROS 좌표는 `(5.487,0.320,-67.107) mm`입니다.
차체 구조물 자체의 CAD 기준 무게중심 높이는 STL 부피 기준 127.933 mm이며,
부품 전체의 실측 질량 2.3263 kg은 유지했습니다. 이 값은 실측 무게중심이 아니라
제공된 형상과 기록된 근사에 따른 계산 결과입니다.
MuJoCo의 초기 자세 전체 무게중심과 URDF 질량 가중 계산값의 일치도 확인했습니다.
`camera_35deg_com.png`의 자홍색 점은 전체 무게중심이고, 빨간 화살표는
카메라의 하향 광학축입니다. 내부 점이 보이도록 차체만 투명하게 렌더링했습니다.
평지 휠 하중은 앞바퀴 각각 약 6.00~6.03 N, 뒷바퀴 각각 약 5.38~5.41 N입니다.
중력만 고려한 30도 경사의 균등 구동 토크는 바퀴당 약 0.136 N·m입니다.
이는 모래 저항·침하·가속·토크 여유를 포함하지 않습니다.

직진·로커 0 자세의 외곽은 길이 **297.72**, 폭 **302.19**, 높이 **181.81 mm**입니다.
폭이 300 mm 제한보다 **2.19 mm 큽니다**. CAD를 원본 치수로 보존했으며 자동 축소하지
않았습니다. 조향 시 외곽은 더 커질 수 있어 규정이 모든 조향 자세에 적용되는지도
확인해야 합니다. 제작 시 치수 조정과 공차 여유가 필요합니다.

학습 전에 실제로 맞추면 좋은 항목은 다음과 같습니다.

- 기계적 로커 제한과 조향 배선/간섭 제한. 현재 ±30도, ±90도는 초기 가정.
- 구동·조향 토크와 속도 제한, 마찰·댐핑, 저수준 제어 응답. 현재 초기 추정값.
- 최종 배선·커넥터·마운트를 포함한 실측 질량과 필요하면 센서 축/원점 보정.
- 사용할 지형과 접촉 모델. 모래 침하·슬립을 이 강체 모델만으로 재현하지는 못함.

ROS 2/RViz와 Isaac Sim에서의 실행은 이 환경에서 검증하지 않았습니다.
특히 다른 엔진에 URDF를 가져오면 mimic이 실제 수동 연동으로 작동하는지 확인해야 합니다.

## 사용

ROS 2 작업 공간의 `src/rover_description`에 이 폴더를 놓고:

```bash
colcon build --packages-select rover_description
source install/setup.bash
ros2 launch rover_description display.launch.py
```

MuJoCo에서는 포터블 URDF보다 **`mjcf/rover.xml`**을 사용하세요.
URDF 직접 로드는 루트를 고정하고 mimic/equality와 액추에이터를 자동으로 만들지 않습니다.
MJCF는 floating base, 로커 equality, 액추에이터와 센서를 포함합니다.
기본 중력은 지상 모사에 맞춘 9.81 m/s²입니다.

검증 및 재생성 스크립트는 Python, NumPy, SciPy, trimesh, vtk, mujoco,
manifold3d, networkx, pymeshfix를 사용합니다.
Python 3.12에서 검증했고 설치 명령은 다음과 같습니다.

```bash
python -m pip install -r requirements.txt
python -m mujoco.viewer --mjcf=mjcf/rover.xml
```

설정 파일을 수정한 뒤:

```bash
python scripts/prepare_component_meshes.py
python scripts/refine_mesh_inertia.py
python scripts/generate_urdf.py
python -m unittest discover -s scripts -p 'test_*.py' -v
python scripts/verify_physics.py
python scripts/render_preview.py
```

요구사항 테스트의 질량·센서 좌표는 이번 버전의 실측 입력을 검증합니다.
해당 입력을 새로 바꾼다면 테스트의 기대값도 새 요구사항에 맞춰 갱신해야 합니다.
URDF 재생성은 모델 설정의 질량·관성·관절값을 읽으며, 부품의 설치 위치를 바꿨다면
부품별 평행축 합산 및 메시 재배치도 함께 갱신해야 합니다.
`prepare_component_meshes.py`는 원본 시각화 STL에서 부품을 분리하고 닫힌 관성용
메시를 준비합니다. 이미 준비된 STL을 그대로 쓸 때는 이 단계를 생략할 수 있습니다.
`refine_mesh_inertia.py`는 부품별 STL과 실측 질량을 읽어 링크 관성을 합산합니다.
설치 위치나 형상을 바꾼 경우 관성용 부품 STL도 해당 링크 좌표에 맞춰 갱신하세요.
이 스크립트를 실행하면 직접 입력한 링크 관성은 부품 계산값으로 갱신됩니다.

`docs/build_sources`에는 이번 CAD 추출/조합 과정의 소스 코드를 보관했습니다.
이 소스는 원본 F3Z를 풀어 만든 중간 폴더와 이전 CAD 검사 결과를 입력으로 사용하며,
위 `scripts/generate_urdf.py`는 완성 패키지의 설정 파일만으로 실행할 수 있습니다.
보관된 CAD 조합 소스는 초기 부품 상자 근사 단계의 기록입니다. 최종 STL 관성
개선은 `scripts/prepare_component_meshes.py`, `scripts/refine_mesh_inertia.py`와
포함된 메시/설정 파일로 재현합니다.
