# KSRC 시뮬레이터 · 강화학습 (`sim/`)

MuJoCo 물리 + 슬립-침하 흙 모델 위에서, 펌웨어와 **같은 C 기구학**(`firmware/common/`)을
ctypes 로 호출해 경로추종 잔차 정책을 학습·평가한다. 로버 전체 개요는 [루트 README](../README.md),
펌웨어 설정은 [firmware/README.md](../firmware/README.md), 전체 학습 명령은 **[CLI.md](CLI.md)**.

> 명령은 특별한 말이 없으면 **저장소 루트(`~/ksrc`) 기준**이다.

### 2026-10-06: 밑단 속도추종 과제

현재 검증 중인 목표는 순수 IK가 만든 바퀴 명령에 잔차를 더해, 모래·슬립·마찰
변화 중에도 요청된 `(vx, vy, ω)`와 실제 차체속도의 오차를 줄이는 것이다.
`task="cmdvel"`은 경로 보상과 경로 관측을 쓰지 않는다. 아래의 경로추종 보상·
`Stage 1` 설명은 기존 `task="path"`에 관한 기록이다.

초기 `s21`은 차체 잔차 3D로 250만 스텝 학습했으나 순수 IK보다 속도오차와
슬립이 나빴다. 원인 감사에서 `cmdvel` 기본 난이도 `d0=0`이 경사·모래 편차를
꺼두고, 경로 완주율 커리큘럼이 속도추종 난이도를 제대로 올리지 못하며,
3.2×4.0m 규사 높이맵을 8×8m 물리에 늘려 경사와 스폰 좌표를 바꾸는 문제를
발견했다. 지금은 `cmdvel` 학습을 **8×8m 절차 규사지형·고정 난이도 0.8**로
분리하고, 원본 대회맵은 본래 크기로 평가한다. 모래 물리값 자체는 아직 실측
전이므로 성능 수치를 실기 보증으로 해석하면 안 된다.

바퀴별 잔차(`action_mode="wheel"`, 4D)와 차체+바퀴 잔차(7D)의 관측 크기 및
학습·비교 CLI를 연결했다. 실기 펌웨어/ROS 브리지는 여전히 3D 차체 명령만
받는다. `velocity_obs=True`는 정책 입력에 **MuJoCo 참 차체속도**를 넣는
진단 실험이며 현재 로버에서 측정 가능한 센서값으로 취급하지 않는다.
학습·평가 명령은 [sim/CLI.md](CLI.md#밑단-목표-속도-추종-cmdvel-2026-10-06)에 있다.

같은 절차 규사지형 난이도 0.8, 센서·토양 랜덤화, 8초, 미학습 시드 20개
(`3000..3019`)에서 순수 IK와 짝지어 평가했다. 값은 최대속도 대비 오차다.
`p90`은 각 에피소드의 90분위값을 낸 뒤 에피소드 간 평균한 값이다.

| 제어 | 평균 병진 오차 | 병진 p90 | 평균 요 오차 | 요 p90 | 슬립 평균 |
|---|---:|---:|---:|---:|---:|
| 순수 IK | 10.70 | 23.05 | 5.55 | 12.76 | 0.16 |
| 센서 이력만 사용한 반복 모방 `s28` | 10.80 | 24.52 | 5.17 | 13.16 | 0.19 |
| 수정 환경에서 센서 이력만 사용한 반복 모방 `s33b` | 10.23 | 23.88 | 5.06 | 12.62 | 0.17 |
| 참속도 관측·이득 0.3 반복 모방 `s32` | **9.61** | **22.48** | **4.96** | **12.24** | 0.17 |
| 참속도·이득 0.6 모방 후 PPO `s31` | 10.05 | 25.19 | 5.04 | 13.49 | 0.21 |

`s32`의 순수 IK 대비 병진 평균 차이는 −1.09 %vmax (짝 bootstrap 95% CI
−1.40~−0.79), 요속도 p90 차이는 −0.52 %ommax (−0.98~−0.05)다.
20회 모두 고착·전복·경계 이탈이 없었다. 다만 이 정책은 **MuJoCo 참속도를
입력으로 쓰는 진단용 모방 정책이지 실기용 RL 정책이 아니다.** 보상 로그가
올랐던 `s31`의 실제 추종 지표는 `s32`보다 나빠졌다. 따라서 추가 PPO 학습만
계속하는 방향은 채택하지 않았다.

모델 선택에 쓰지 않은 별도 60개 시드(`6000..6059`)에서 `s32`의 병진 평균
오차는 IK 11.53→10.54 %vmax (짝 차이 −0.98, 95% CI −1.30~−0.59),
요속도 평균은 6.13→5.56 %ommax (−0.56, −0.73~−0.39)였다. 그러나
병진 p90은 25.69→25.98, 요속도 p90은 14.07→14.16으로 개선되지
않았다. 슬립 평균도 0.17→0.18, 침하 평균은 최대 침하량 대비
2.70→2.88%로 늘었다. 60회 모두 고착·전복·경계 이탈은 없었다.
따라서 **평균 오차 개선은 재현되지만 꼬리 오차와 토양 비용까지 개선한
정책은 아니다.** 실측 대지속도 추정기도 아직 없다.

`s33b`는 학습 라벨을 MuJoCo 참속도 비례 제어기에서 받되, 실행 입력에는
명령·엔코더·조향·IMU의 1초 이력만 쓴다. 수정된 중앙 스폰·리셋 환경에서
다시 학습했다.
별도 60개 시드(`8000..8059`)에서 병진 평균 오차는 IK 11.08→10.19
%vmax (짝 차이 −0.89, 95% CI −1.07~−0.69), 요속도 평균은
5.94→5.47 %ommax (−0.48, −0.60~−0.34)였다. 병진 p90은
24.08→23.81 (CI −1.17~+0.77), 요속도 p90은 13.79→13.98
(−0.42~+0.93)로 확실한 개선이 아니다. 슬립·침하도 조금 늘었고
고착·전복·경계 이탈은 각 0/60이다. **센서 관측만으로도 평균 추종이
조금 좋아질 수 있다는 증거**지만, 극단 오차와 외란 복구는 아직 해결되지
않았다. 이는 참속도 없이 바로 실기에 쓸 수 있다는 검증이 아니다.

학습 분포보다 강한 절차지형 난이도 1.0·바퀴별 마찰장 진폭 0.35로 올린
20개 별도 시드(`10000..10019`)에서도 `s33b`의 병진 평균 오차는
12.00→11.18 %vmax (짝 CI −1.28~−0.24)였다. 병진 p90은
28.30→26.81이지만 CI −3.95~+0.56으로 불확실했고, 요속도 p90은
14.95→15.99로 나빠질 가능성이 남았다. 이 수치는 시뮬레이션 내
분포 밖 시험이며 실제 모래 물성 검증은 아니다.

1 N 외력을 0.3초 넣은 20개 시드(`9000..9019`)에서는 `s33b`의 외력이
**끝난 뒤 1초** 병진 오차가 IK 12.32→12.54 %vmax (짝 CI
−0.77~+1.63)로 개선되지 않았다. 같은 구간 요속도 오차는
5.13→4.75 %ommax (−0.65~−0.11)였지만, 에피소드 전체 요속도
p90은 11.15→13.00 (+0.14~+3.90), 슬립 평균은 0.16→0.19로
나빠졌다. 참속도 비례 제어기조차 외력 뒤 병진 오차 개선이 불확실했다.
따라서 현재 정책을 외란 복구 제어기로 간주할 수 없다.

후속 가설도 같은 기준으로 기각했다. 참속도 비례 제어기에 1초 누설 누적 보정
`Ki=0.1/s`를 더하자 보통 지형 20쌍(`11000..11019`)에서는 평균 병진
오차가 9.68→9.47 %vmax로 줄었지만 병진 p90은 21.32→22.09로
커졌다. 외력 20쌍(`9000..9019`)에서 외력 종료 뒤 1초 병진 오차는
비례 제어기 12.10→누적 보정 13.25로 악화됐다. `s33b` 행동 절댓값을
0.25로 자른 시험 30쌍(`13000..13029`)도 병진 p90 22.40→22.87로
나빠져 상한을 채택하지 않았다.

큰 오차에 계속 기울기를 주는 이차 비용(`--w-tail 0.1`)으로 `s33b`를
10만 스텝 더 학습한 시험도 실패했다. 20개 검증 시드(`3000..3019`)에서
학습 전 `s33b`의 병진 평균/p90은 10.23/23.88 %vmax였는데,
일반 학습률 `3e-4`의 10만 스텝 후 11.25/25.08, 학습률을 `3e-5`로
낮춘 10만 스텝 후에도 10.42/25.50이었다. 낮은 학습률의 모델은
순수 IK 대비 병진 p90 차이 +2.45 %vmax (짝 CI +0.50~+4.73)와
슬립 평균 0.16→0.19를 기록했다. 따라서 **현재 보상 변경·PPO 연장은
채택하지 않고 `s33b`를 진단 기준선으로 보존한다.** 이 실험은 10만
스텝과 한 가중치의 결과이며 다른 학습 구조의 불가능성을 뜻하지 않는다.

실기 목표를 판단하려면 명령과 시간 동기화된 대지속도 추정치, 엔코더·조향각·
IMU·전압·구동 명령 로그, 그리고 모래에서의 실제 이동 기준이 필요하다.
ROS의 `/odom`은 현재 MuJoCo 참값이고 `ros/mujoco_bridge.py`는 경로 과제
관측으로 고정돼 있어 이 `cmdvel` 정책을 그대로 실기나 Nav2에 연결한
상태가 아니다. 먼저 실제 속도 추정의 지연·오차를 측정하고, 같은 오차를
시뮬 관측에 넣어 독립 시드와 외력·급경사에서 재검증해야 한다.

이번 감사에서 속도추종용 절차지형의 스폰을 중앙 주행 가능 지점으로 제한해,
경로용 스폰 때문에 생긴 경계 이탈 15%를 제거했다. 리셋 시 같은 정지 상태의
센서를 이력 길이만큼 다시 읽던 문제도 고쳤다. 현재 이력의 첫 프레임은 한 번
읽어 복제하므로 이력 길이가 센서 난수열을 바꾸지 않는다. 외력 펄스 옵션은
지형·명령 난수와 별도 난수열로 동작한다.
수정된 절차지형에서 IK 10회(`9000..9009`)를 따라 기록한 4,000개 주행
지점 중 풋프린트 규모 경사가 10° 이상인 비율은 17.6%, 20° 이상은
4.7%였다. 따라서 이번 비교가 평지에만 국한되지는 않지만, 경사별 성능은
별도로 분해해서 보아야 한다.

## 구성

### `sim/rl/` — MuJoCo 물리 + 강화학습

| 파일 | 역할 |
|---|---|
| `config.py` | 로버 물리 파라미터 + 센서/구동 노이즈. 출처를 [확정]/[추정]/[미정] 3등급 표기 |
| `mjcf.py` | config → MuJoCo MJCF 모델 생성 |
| `terramech.py` | 슬립-침하 모델. 고착 재현의 핵심 |
| `terrain.py` | 절차 지형 생성 · 대회장 맵 로드 · 주행가능 마스크 · 미세요철 교란 |
| `path.py` | 기준경로 생성 + 홀로노믹 pure pursuit (Nav2 컨트롤러 미러링) |
| `reward.py` | 단일 보상 함수와 가중치 (`RewardCfg`) |
| `env.py` | Gymnasium 환경 |
| `train.py` | PPO 학습 (stable-baselines3) |
| `eval.py` | 대회장 지형 평가. 고전 제어 기준선 4종과 비교 |
| `traction.py` | 고전 제어 기준선 (경사스케줄 듀티 제한 / 엔코더 TCS) |
| `nets.py` | teacher-student 신경망 (특권 인코더 / 적응 모듈) |
| `distill.py` | teacher → student 증류 (DAgger + 잠재변수 회귀) |
| `probe_teacher.py` | teacher 가 특권정보를 실제로 쓰는지 진단 |
| `view.py` | MuJoCo 뷰어 (정책 재생). `--path` 로 지정 경로, `--stage1` 로 학습 조건 재현 |
| `draw_path.py` | 지형 지도에서 마우스로 경로 찍기 |
| `check_model.py` | 모델 물리 검증 13종 |
| `test_terramech.py` | 견인력 곡선·고착 재현 검증 |
| `plotlog.py` | 학습 로그 → 그림 |
| `draw.py` | 모델 2D 단면 렌더 |

## 실행 명령

전체 인자는 **[CLI.md](CLI.md)** 에 있음. 아래는 자주 쓰는 것만임.

### 빌드 · 검증

```bash
cd sim && bash build.sh          # 기구학 C → libksrc_common.so
cd rl  && python3 check_model.py # 물리 검증 13종
python3 test_terramech.py        # 견인력 곡선 검증
```

### 학습

```bash
cd sim/rl

# Stage 1 — 경로추종 sanity check (경로 세트 고정, 랜덤화·교란·커리큘럼 OFF)
python3 train.py --steps 1000000 --envs 16 --terrain sand --stage1 --out runs/s5_reward

# Stage 2 — 랜덤화·커리큘럼 켜고 특권 관측(teacher) 붙임
python3 train.py --steps 4000000 --envs 16 --teacher --terrain sand --out runs/foo
```

| 옵션 | 뜻 |
|---|---|
| `--stage1` | 경로 세트 고정(10개) + 랜덤화·노이즈·교란·커리큘럼 전부 OFF. **3D 잔차가 경로추종을 배우는지만** 본다 |
| `--terrain sand\|rock\|proc` | `sand`/`rock` 은 대회장 맵 고정, `proc` 은 절차 생성 |
| `--teacher` | 특권 관측을 붙임 (Stage 2) |
| `--path-seed` / `--n-paths` | Stage 1 경로 세트. **학습과 평가는 다른 seed** 를 써야 함 |
| `--gamma` | 기본 0.998 (시상수 10초). 0.99 는 50Hz 에서 2초라 완주 보너스가 안 보임 |
| `--drive-align-gate-deg` | 기본 10°. 60° 초과 큰 방향 전환 후 구동 재개 오차, 0이면 이전 동작과 비교 |
| `--w-energy` | 현재 미지원: 차축 부하 모델 검증 전에는 오류를 내고 학습을 시작하지 않음 |

### 현재 학습 환경 (`sim/rl/env.py`, `train.py`)

| 구성 | 현재 구현 |
|---|---|
| 물리·제어 주기 | MuJoCo 2 ms 물리 스텝 10회당 정책 1회(50 Hz). 에피소드 최대 20초/1000스텝 |
| 기준 제어 | 경로 위 pure pursuit가 `cmd_nom=(vx, vy, ω)` 생성 → 정책의 3차원 행동 `a∈[-1,1]^3`에 `(0.03 m/s, 0.03 m/s, 0.10 rad/s)`를 곱해 가산 → 공유 C 스워브 IK → 바퀴별 개루프 PWM 듀티·조향각 |
| 저수준 보호 | 바퀴 속도 한계를 넘으면 차체 명령을 공통 비율로 축소. 목표 조향각이 한 주기에 60° 넘게 바뀌면 네 바퀴가 목표의 10° 이내로 정렬될 때까지 구동 보류 |
| 경로·시작 | 경사 최대 21°·단차 최대 40 mm 마스크에서 바퀴 외접 반경 약 0.21 m와 여유 0.03 m를 더 확보한 경로를 생성 (2026-10-03 실측 치수, 이전 0.19 m). 고정 경로 세트에서는 경로 길이의 앞 0~60% 위치에서 시작하고 투영기 두 개도 그 위치에서 초기화. 초기 기수는 그 지점 접선의 ±30° |
| 관측 | 프레임당 36개(`cmd_nom`, 직전 바퀴 명령·엔코더 속도·조향각, 자세·IMU, 0.30/0.80 m 경로 샘플 2점, 횡오차, 기수오차의 cos/sin, 제어기 선행 목표점과 선행 거리 `L`, 직전 행동) × 50프레임 = 1800차원(1초 이력). `--teacher`는 흙·슬립·침하 등 특권값 43개를 추가해 1843차원 |
| 종료 | 목표까지 경로 잔여길이와 실제 거리 **모두** 0.25 m 미만이면 성공. 전복(roll/pitch 60° 초과), 최근 2초 이동 0.02 m 미만이면서 슬립 0.5 초과, 경계 이탈은 실패 종료. 20초 도달은 시간 만료 |

위 Stage 1 실행 예시(`--terrain sand --stage1`)는 고정 경로 10개(seed 1234), 원본 대회 높이맵,
고정 규사 파라미터를 쓴다. **센서·구동 노이즈, 물리 파라미터 랜덤화, 높이맵
교란, 커리큘럼은 꺼진다.** 경로 선택·시작 위치·기수·순항속도는 여전히 매
에피소드 달라진다. `train.py`의 `--terrain` 기본값은 `proc`이므로 Stage 1에서는
`--terrain sand`를 명시한다. `--terrain proc --stage1`은 **경로만 sand 맵에서
생성하고 지형은 proc으로 만드는 불일치**가 있어 현재 비교에 쓰지 않는다.
Stage 1 학습 경로 10개를 2 cm 간격으로 표본화하면 7개에 10° 이상 구간이
있고 6개는 시작점보다 끝점이 높다. 최고 경사는 약 15.3°다. 20° 이상과
30° 램프는 이 고정 경로에 포함되지 않으므로, 현재 Stage 1 결과로 급경사
등판 성능을 판단할 수 없다.
평가 경로는 별도 seed(기본 4321)로 생성해 같은 경로 암기를 구분한다.
암석맵(`rock`)은 이 이격(당시 0.22m, 지금 0.239m)을 적용하면 긴 2m 고정 경로가 나오지 않아
`--terrain rock --stage1`이 오류로 중단된다. 암석 구간은 별도의 짧은 임무
길이·목표 판정이 필요하며, 현재 Stage 1 성능 비교는 규사맵 기준이다.

Stage 2(`--stage1` 없음)는 `--terrain sand|rock`이면 해당 대회 높이맵을 쓰고
매 에피소드 미세요철을 교란한다(기본 표준편차 `0.020 m × 난이도`). `proc`이면
8×8 m 절차 지형을 새로 만든다. 흙 다짐·두께와 바퀴별 마찰 패치, 미측정
질량·로커 스토퍼, 배터리 전압, 엔코더·IMU 오차, 서보 응답, 0~2스텝 제어
지연, 저역통과된 측위 오차를 랜덤화한다. 최근 100개 에피소드 성공률이
60% 이상이면 난이도를 0.05씩 올린다. 학습기는 SB3 PPO, 관측·보상
`VecNormalize`, 기본 `γ=0.998`, 512스텝/환경 rollout, batch 4096,
6 epoch, 학습률 `3e-4`다. `--teacher`는 이 Stage 2의 선택 사항이다.

**현재 관측 제약:** 학습용 추종기는 `L=clip(pp_k_v × v_cruise, pp_l_min, pp_l_max)`만큼
경로를 따라 앞선 목표점 하나를 사용한다. 정책 관측에는 이 점의 차체좌표와
`L`을 별도로 넣고, 0.30/0.80 m 경로 샘플 두 점은 경로 모양을 전달한다.
Pure Pursuit의 목표점 하나와 경로 샘플 두 점은 서로 다른 역할이다.
ROS에서 현재 쓰는 Nav2 Omni MPPI에는 단일 Pure Pursuit 목표점이 없으므로
`/plan`에서 같은 선행 거리 규칙으로 정책용 참조점을 만든다. 나중에 제어기를
Pure Pursuit으로 교체하면 실제 선택한 목표점을 이 필드에 전달해야 한다.
관측이 1650→1800차원으로 바뀌어 기존 체크포인트는 새 환경에 로드되지 않으며
새 입력으로 다시 학습해야 한다. pure pursuit 명령·lookahead와 36차원 프레임의
`e_y`·`e_psi`는 같은 잡음 포함 추정 자세로 계산한다. 보상·종료 판정은 참값을
쓴다. 실기 투입에는 Nav2 측위·경로에서 같은 입력을 공급해야 하며,
ROS 브리지의 관측과 Stage 2 관측의 수치적 일치는 아직 별도 검증이 필요하다.

### 현재 보상 함수 (`sim/rl/reward.py`)

정책 행동을 적용해 **물리를 진행한 뒤** 참 위치로 보상을 계산한다. 경로 호길이
진행량을 `p=clip(Δs/(v_cruise·Δt), 0, 1)`, 실제 이동량을
`m=clip(‖Δxy‖/(v_cruise·Δt), 0, 1)`로 정규화한다. `Δs`는 한 주기의 실제
이동거리로 상한을 두어 코너를 잘라도 가짜 진행 보상을 받지 않는다.
`e_y`는 단조 진행 투영기의 경로 횡오차, `d_route`는 전체 경로 선분까지의
최근접 실거리, `e_psi`는 차체 기수와 경로 접선 사이의 각도다.
실제 이동 방향 `e_course`는 진단으로 기록하지만 현재 보상에는 쓰지 않는다.
경로 중앙으로 복귀하는 대각 이동에 방향 게이트를 걸면 교정 행동도 벌주기 때문이다.

```text
G = exp(-(e_y / 0.08 m)^2) · max(0, cos(e_psi))
Phi(s) = -0.25 d_route / (v_cruise·Δt)
F(s,s') = gamma·Phi(s') - Phi(s)       # 종료/시간만료 상태의 Phi = 0
r_step = 0.20 p + 0.80 p G
       - 0.04 m min((e_y / 0.08 m)^2, 4)
       + F(s,s')
       - 0.01 m min((e_psi / 0.35 rad)^2, 4)
       - 0.01 mean((a_t - 2a_(t-1) + a_(t-2))^2)
       - 0.06 mean(a_t^2)
```

완주 `+20`, 전복 `-10`, 고착 `-5`, 경계 이탈 `-10`은 해당 스텝에 한 번
더한다. 차체 헤딩 게이트는 논문과 같은 `max(0, cos(e_psi))`이다. 따라서
게걸음·후진에서는 **정렬 보상 80%가 0**이 되고 기본 진행 20%만 남는다.
이는 예전의 "차체 방향과 무관한 스워브" 목표에서 논문식 전방 선호로 바꾼 선택이다.
논문의 단위와 원계수는 제어주기·속도가 달라 복사하지 않았다.
옆방향 복귀가 당장 경로 진행을 줄여도 학습 신호를 얻도록 경로까지의
실거리 잠재함수를 추가했다. 이 항은 논문에는 없는 스워브용 확장이다.
단조 투영기의 국소 `e_y`는
코너에서 선분이 바뀌며 점프하므로 이 항에 쓰지 않는다. 전체 선분 최근접
실거리는 한 주기의 실제 위치 이동량보다 빠르게 변할 수 없다. 잠재함수는
할인율 `gamma`와 일치시키고 종료 시 값을 0으로 처리해 왕복 이동이
같은 시간 동안 정지해 있는 것보다 추가 할인 보상을 만들지 못하게 했다.
보상 설정은 `RewardCfg` 하나만 사용한다. 가중치를 수정할 때는
`reward.py`를 변경하고 새 `--out` 디렉터리에서 학습한다. 학습 시작 시
`reward.py`와 보상 조립·종료 판정이 있는 `env.py`의 사본을 실행 디렉터리의
`src/`에 저장하므로 실험별 공식을 확인할 수 있다.
전력·에너지·슬립·침하는 **현재 진단 지표이지 보상 항이 아니다.** 차축 부하
모델이 미검증이라 에너지 가중치 옵션 `--w-energy`는 오류를 내고 중단한다.

| TensorBoard 항목 | 보상에서 하는 일 | 해석 |
|---|---|---|
| `reward/prog` | 경로 호길이 진행 `+0.20p` | 큰 횡오차에서도 전진할 유인을 남김 |
| `reward/align` | 횡오차·차체 헤딩 정렬을 통과한 진행 `+0.80pG` | 헤딩 90° 이상이면 0 |
| `reward/lat` | 이동 중 횡오차 벌점 | 음수. 0에 가까울수록 좋음 |
| `reward/recover` | 전체 경로 실거리의 할인 일치 잠재함수 변화 | 같은 시간의 왕복/정지에 추가 이득 없음 |
| `reward/head` | 이동 중 차체 기수오차의 유계 이차 벌점 | 논문식 헤딩 항을 수치적으로 제한 |
| `reward/course` | 기본 보상에서는 0 | 실제 이동 방향오차는 진단 지표로 남김 |
| `reward/smooth` | 행동의 2차 차분 벌점 | 잔차 명령이 갑자기 바뀌는 것을 억제 |
| `reward/resid` | 행동 크기 벌점 | 지속적으로 큰 잔차를 쓰는 것을 억제 |
| `reward/goal` | 경로 완주 시 한 번 `+20` | 에피소드 평균은 대략 `20 × 완주율` |
| `reward/tip` | 전복 시 `-10` | 실패 종료 벌점 |
| `reward/stuck` | 고착 시 `-5` | 실패 종료 벌점 |
| `reward/oob` | 경계 이탈 시 `-10` | 실패 종료 벌점 |

`reward/*` 그래프는 스텝 보상이 아니라 **에피소드별 항목 합계**를 최근 종료된
200개 에피소드에서 평균한 값이다. 에피소드 길이가 바뀌면 `align` 합계도
달라지므로, 경로추종 개선 여부는 `rollout/e_y_m`, `rollout/e_y_p90`,
`rollout/course_m`, `rollout/success`, `rollout/a_use`를 함께 확인한다.
이전 가중치(`sigma_y=0.10`, `w_lat=0.03`, `w_head=0.02`)로 학습한
`s5_paper_heading` 100만 스텝 정책은 미학습 경로 30쌍에서 IK와 완주율은
같고, 기수오차는 3.93° 줄었지만 평균 횡오차는 5.00 mm, 슬립은 0.07 늘었다.
그래서 20~30 mm 횡오차 차이를 더 구별하고 중복된 헤딩 이차 벌점을 줄였다.
급경사 보정까지 막지 않도록 잔차 벌점 `0.06`은 유지했다. **새 가중치의 성능은
재학습 후 같은 미학습 경로에서 IK와 비교해야 한다.**

로그는 `runs/<이름>/tb` 로 감. 실행마다 따로 쌓이므로 **전부 비교하려면 `--logdir runs`** 를 줌.
현재 `RoverEnv`는 조향 목표가 한 주기에 60° 넘게 바뀌는 큰 방향 전환에서만
네 바퀴 구동을 함께 보류하고, 모두 목표각의 10° 이내에 들면 다시 구동한다.
학습·평가·ROS 주행에 공통 적용된다. 저장된 `runs/s2`는 이 조향 대기와
새 경로추종 보상을 넣기 전에 학습했으므로 새 보상의 성능을 나타내지 않는다.
STM32 펌웨어도 같은 규칙(`firmware/common/drive_align_gate.c`)을 50Hz 제어주기에 적용한다.
실기에서는 서보 현재각을 버스로 읽어 판정하며, 아직 실기 검증 전이다.

### 재생 (play)

```bash
cd sim/rl

# 순수 기구학 (잔차 0) — 기준선 확인
python3 view.py --terrain sand --d 1.0 --realtime      # --realtime 0.5 로 느리게

# 학습된 정책.  vecnorm 을 빼면 관측 스케일이 어긋나 결과가 무의미함
python3 view.py --terrain sand --stage1 --realtime \
        --model runs/s2/final --vecnorm runs/s2/vecnorm.pkl

# 학습 중 저장되는 최신 정책을 별도 MuJoCo 뷰어에서 자동 재생
python3 view.py --terrain sand --stage1 --watch-run runs/s9_watch

# 지형만 보기 (물리 정지)
python3 view.py --terrain rock --static
```

**`--stage1` 을 주면 학습과 같은 조건**(경로 세트 고정, 랜덤화 OFF)으로 재생함.
안 주면 경로가 매번 새로 생성되고 노이즈가 켜져서 학습 조건과 달라짐.

### 평가 · 진단

```bash
cd sim/rl
# 학습에 쓰지 않은 경로 세트(seed 4321)에서 같은 스폰·흙 조건으로 짝비교
python3 compare_policy.py --model runs/s2/final --vecnorm runs/s2/vecnorm.pkl \
        --episodes 30
# 위 비교가 통과하면 같은 경로에서 구동·센싱 노이즈와 흙 랜덤화도 확인
python3 compare_policy.py --model runs/s2/final --vecnorm runs/s2/vecnorm.pkl \
        --episodes 30 --randomize

python3 eval.py --arena --terrain sand --episodes 30 \
        --model runs/foo/final --vecnorm runs/foo/vecnorm.pkl
python3 probe_teacher.py --model runs/foo/final --vecnorm runs/foo/vecnorm.pkl
tensorboard --logdir runs/foo/tb
```

`compare_policy.py` 는 순수 IK(잔차 0)와 학습 정책을 같은 시드로 실행하고,
완주율뿐 아니라 횡오차 평균·p90, 기수오차, 슬립, 시간, 잔차 사용률을 비교한다.
`runs/s2` 의 학습 경로 기본 seed 는 1234 이므로 평가 기본값 4321 과 다르다.
경로추종 보조라면 완주율만이 아니라 횡오차 평균·p90도 기준선보다 좋아져야 한다.
차체 기수오차는 기록하되, 게걸음·후진 중에는 경로추종 실패로 간주하지 않는다.
RViz/Nav2 브리지는 기본값에서 잔차 0(순수 IK)이고, `rl:=true` 일 때만 정책을
적용한다. 이 재생 평가는 Nav2 MPPI 명령과는 다른 pure pursuit 명령으로 잰 결과다.
브리지는 `/plan` 경로와 필터링된 Nav2 명령으로 정책 관측의 경로 관련 필드를
매 주기 채운다. 따라서 RViz 시험은 정책 적용 확인용이며, 성능 수치는 별도로 재야 한다.
현재 3D 잔차의 크기는 `config.py` 의 `d_vx_max/d_vy_max/d_om_max` 로 정해진다.
옛 `--clip-steer-deg`/`--clip-duty`는 현재 3D 행동에 영향이 없어서 제거했다.

## 설계상 중요한 선택

**정책은 기구학을 대체하지 않고 보정함.** 행동은 차체속도 잔차 3개
`(Δvx, Δvy, Δω)`이며, 기본 명령에 더한 뒤 공유 스워브 IK로 보낸다.
`config.py`의 `d_vx_max/d_vy_max/d_om_max`가 잔차 권한을 정한다.
RViz 주행에서는 `rl:=false` 또는 `/set_rl`로 잔차를 0으로 만들 수 있다.

**쿨롱 마찰로는 고착을 재현할 수 없음.** MuJoCo 기본 접촉은 미끄러지면 견인력이
`μN` 으로 고정이라 시뮬 로버가 자기 구덩이를 못 팜. 실제 모래는
`슬립↑ → 침하↑ → 저항↑ → 슬립↑` 의 양의 되먹임이 있고 그게 곧 고착임.
`terramech.py` 가 전단곡선을 마찰계수로 주고 침하를 상태로 적분해 재현함.

**기본 보상은 2026년 4WIS 논문의 진행·정렬·횡오차·헤딩오차·매끄러움 항목을
스워브에 맞게 변형한다.** 진행의 20%는 남기고, 80%는 횡오차와 **차체 헤딩**
게이트를 통과해야 받는다. 중앙으로 복귀하는 대각 이동을 벌주던 **실제 이동방향**
게이트는 제거했다. 경로 실거리 복귀는 할인 일치 잠재함수로 학습 신호를 주며,
같은 시간의 왕복 이동으로 점수를 만들 수 없다. 잔차 크기와 행동 2차 차분
벌점, 완주·전복·고착·경계 항도 유지한다. 보상 가중치는 `reward.py`의
`RewardCfg`에서 직접 수정한다.
최종 목표 기수는 Nav2의 도착 자세 제어가 맡는다.

**컨트롤러와 정책 관측은 측위 추정치를, 보상·판정은 참값을 씀.** `e_y`와
`e_psi` 관측도 pure pursuit와 같은 추정 자세에서 계산해 센서 랜덤화가 함께
적용된다. 실기에서는 이 자세를 Nav2 측위에서 공급해야 한다.

**측위 잡음은 저역통과로 줌**(τ=0.2 s). 50 Hz 백색잡음을 주면 조향이 지터를 따라
떨어 `scrub` 이 17배가 됨. 실제 측위는 EKF 가 오도메트리와 ICP(5~15 Hz)를 융합해
매끄러운 출력을 내므로 관측 잡음 대역이 제어 대역보다 훨씬 낮음.

**플래너 경사 상한은 현재 흙 모델의 견인력 가정에서 유도함.**
`max_slope_deg = 21.0°` 임. 규사 프리셋의 최대 마찰계수 0.55에서 침하 후
굴림·압밀 저항 약 0.14를 빼면 `atan(0.41) ≈ 22°`이며, 플래너에는 21°를 쓴다.
실제 규사의 마찰계수·침하 저항은 아직 측정하지 않았으므로 이는 실기 등판한계
측정값이 아니다. 30° 구간은 현재 Nav2 맵에서 통과 불가로 표시한다.

**학습 지형은 대회장 맵 고정 + 미세요철 교란임.** 거시 구조(램프·평지 배치)는
건축물이라 안 변하고, 변하는 것은 바퀴자국 규모(수 cm)임. 맵 하나에 고정하면 그
한 장의 요철까지 외우는데 모래는 대회 당일까지 움직임(다른 팀 주행·갈퀴질·습도).
암반 지형은 학습에서 빼고 일반화 검증용으로 남김.

**흙은 규사 하나로 고정하고 상태만 랜덤화함.** 대회장이 나무 프레임 위 규사 구조라
암석·경질토를 섞을 이유가 없음. 대신 다짐/습도(`μ` 0.60~0.82)와 두께(8~60 mm)를
난이도에 따라 흔듦.

**로버 형태는 랜덤화하지 않음.** 치수는 측정으로 확정되는 값이라 흔들 이유가 없음.
대신 실기에서 매 순간 변하고 측정으로 없앨 수 없는 것을 흔듦 — 배터리 전압(0.83~1.05),
엔코더 양자화·잡음, IMU 바이어스, 서보 지연·데드밴드, 제어 지연, 측위 오차.

## 학습 현황

항목별 전체 상태 표는 [루트 README](../README.md#현재-상태).

### `s3_path_reward` 검증 (2026-09-29)

아래 수치는 **경로 중간 스폰의 투영기 초기화와 로버 크기 이격을 고치기 전**의
기록이다. 현재 환경·Nav2 설정의 성능 수치가 아니며, 이 체크포인트를 새 환경의
평가 기준으로 재사용하지 않는다. 경로 수정 후·보상 수정 전 학습은
`runs/s4_route_fix`에 저장했고, 현재 보상의 새 학습은 `runs/s5_reward`를 쓴다.
100회는 서로 독립인 경로 100개가 아니라 고정된 경로 30개를 재사용했으므로,
표의 에피소드 단위 bootstrap 구간을 새 경로 전반의 불확실성으로 해석하지 않는다.

학습 경로 seed 1234와 다른 seed 4321의 규사 경로 30개에서, 같은 스폰·경로를
쓴 100 에피소드 짝비교 결과다. Stage 1과 같은 무잡음·비랜덤 물리,
pure pursuit 명령, 조향 대기 10° 조건이다. `4M`과 `18M`은 **같은 두 번째
학습 실행**의 체크포인트와 최종 모델이다. 첫 번째 실행은 약 246만 스텝에서
끝났고 같은 출력 폴더에 새 학습을 시작했으므로, 두 실행을 이어 학습한 것은 아니다.

| 지표 | 순수 IK | 4M 정책 | 18M 정책 |
|---|---:|---:|---:|
| 완주율 | 90% | 91% | 91% |
| 평균 횡오차 | 27.4 mm | 37.2 mm | 37.0 mm |
| 횡오차 p90 | 58.6 mm | 66.9 mm | 67.2 mm |
| 평균 슬립 | 0.18 | 0.24 | 0.23 |
| 잔차 평균 절댓값 | 0% | 77.8% | 84.2% |
| 차체 명령 포화 주기 | 6.1% | 23.0% | 31.1% |

18M의 순수 IK 대비 완주율 차이 `+1%p`의 짝 bootstrap 95% 구간은
`[-3, +5]%p`(RL만 3회, IK만 2회; McNemar exact `p=1.0`)라 개선 근거가 없다.
평균 횡오차 차이 `+9.6 mm`의 95% 구간은 `[+7.7, +11.5] mm`다.
학습 로그의 에피소드 보상 증가는 주로 `reward/smooth` 벌점이 약 `-26`에서
`-8`로 줄어든 데서 왔고, 4M→18M의 경로추종 개선으로 이어지지 않았다.
같은 미학습 경로의 앞 30쌍(seed 1000~1029)에서 18M 정책 행동에
`rl_scale=0, 0.25, 0.5, 1`을 곱해 확인한 평균 횡오차는 각각
`40.2, 41.7, 44.7, 50.3 mm`였다. 0.25배에서도 순수 IK보다
`+1.5 mm` 나빴다(짝 bootstrap 95% 구간 `[+0.3, +2.6] mm`).
따라서 현 정책은 출력만 줄여도 경로추종 개선 근거가 없으며, 무잡음 조건에서
먼저 실패하므로 노이즈·랜덤화 평가는 후순위다.
원인 진단용 20쌍에서는 **같은 보상식으로 계산한 총점도** 미학습 경로에서
순수 IK `319` 대 RL `275`, 학습 경로에서도 `336` 대 `308`이었다.
따라서 현재 보상식이 높은 횡오차를 더 좋게 평가해서만 생긴 결과는 아니다.
최종 정책 행동의 절댓값이 0.95를 넘는 주기 비율은 `vx/vy/ω` 각각
`69/73/62%`였고, 세 축 중 하나를 꺼도 순수 IK보다 횡오차가 컸다.
PPO 로그에서 `train/approx_kl` 중앙값은 첫 400만 스텝 `0.030`에서
마지막 구간 `0.244`로, `train/clip_fraction` 중앙값은 `0.18`에서
`0.48`로 커졌다. 잔차 상시 포화와 과한 정책 업데이트를 먼저 점검해야 한다.
이는 **Nav2 MPPI 주행 평가가 아니라** 학습과 같은 pure pursuit 명령을
미학습 경로에서 시험한 결과다. 기본 ROS launch의 `rl:=true`는 여전히
구형 `runs/s2` 모델을 지정하며 최신 체크포인트를 자동으로 고르지 않는다.

미확정 파라미터는 `config.py` 에 `[미정]` 으로 표시돼 있고 전부 도메인 랜덤화
범위로 덮여 있음.

### 알려진 제약

- **현재 규사 프리셋에서는 30° 램프를 못 오름.** `mu_max=0.55`, 기본 저항
  `c_r=0.05`라 침하 전부터 순견인 상한 0.50이 `tan(30°)=0.577`보다 작다.
  이는 미보정 흙 모델의 결과이며 실기 한계나 기구 변경 필요성을 입증하지 않는다.
- **`terramech.py` 가 `wheel_w` 를 쓰지 않음.** 바퀴 폭·접지압 효과를 정량화할 수 없음
- **`rollout/duty_sat`·`rollout/duty_use`는 현재 유효하지 않음.** `env.py`에서
  카운터를 0으로 초기화하지만 주행 중 갱신하지 않아 그래프가 0으로 남는다.
  잔차의 실현 한계는 우선 `rollout/cmd_sat`로 확인한다.
- **다리 하우징이 바퀴축 아래 30.35 mm 에 고정.** 지상고 9.6 mm 를 결정하는 값이고
  바퀴를 규정 한계(반경 58.25 mm)까지 키워도 지상고는 27.9 mm 가 상한임
