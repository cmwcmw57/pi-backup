# CLI 레퍼런스

로버 펌웨어를 빌드·플래시하고, 시리얼 터미널로 조작하는 방법.

---

## 1. PC에서 실행하는 명령

### 빌드 / 플래시

```bash
cd ~/ksrc/firmware/src2026-rover-firmware

./build.sh              # 빌드만
./build.sh --flash      # 빌드 후 ST-Link로 플래시
./build.sh --clean      # build/ 지우고 전체 재빌드
```

`arm-none-eabi-gcc`가 PATH에 없으면 CubeIDE에 번들된 툴체인을 자동으로 찾습니다. CubeIDE를 열 필요 없습니다.

### 시리얼 터미널

```bash
python3 -m serial.tools.miniterm /dev/ttyACM0 115200
```

나가기: `Ctrl+]`

ST-Link의 가상 COM 포트입니다. 보드와 PC를 잇는 USB 케이블 하나가 **플래시와 터미널 둘 다** 담당합니다.

### 조이스틱 텔레오퍼레이션

```bash
python3 ~/ksrc/pi/teleop/teleop_joystick.py
```

| 인자 | 기본값 | 설명 |
|---|---|---|
| `--port` | `/dev/ttyACM0` | 시리얼 장치 |
| `--baud` | `115200` | 보레이트 |
| `--rate` | `20.0` | 명령 전송 주기(Hz). 30 넘기면 펌웨어 파서가 바이트를 흘리기 시작 |
| `--format` | `ascii` | `ascii`=실제 로버(`V ...` 줄), `binary`=시뮬레이터 |
| `--max-lin` | `0.5` | 패드 최대 변위에 대응하는 \|vx\|,\|vy\| (m/s) |
| `--max-ang` | `2.0` | 패드 최대 변위에 대응하는 \|ω\| (rad/s) |

조작: 왼쪽 패드 드래그=병진, 오른쪽 패드=회전, `Q`/`E`=회전(병진과 동시 가능), `Space`=정지, `Esc`=종료.

시뮬레이터에 붙일 때만 `--format binary`를 씁니다.

## 2. 터미널 명령어

대소문자 구분 없음. 한 줄 입력 후 엔터.

### 화면 / 도움말

| 명령 | 인자 | 설명 |
|---|---|---|
| `LOG` | 없음 | 주기 로그 + 모터 테스트 단계 메시지 + 제어주기 상태줄 on/off **토글**. 기본 ON, **텔레옵이 시작되면 자동 OFF** |
| `ECHO` | 없음 | 입력 문자 에코 on/off **토글**. 기본 ON |
| `HELP` | 없음 | 명령 목록 |

> **작업 시작할 때 `LOG` 한 번** 치고 시작하세요. 기본 상태에서는 엔코더 로그가 0.1초마다 5줄씩 쏟아져 입력도 응답도 읽을 수 없습니다. `LOG`를 끄면 완전히 무음이 되고, 내가 친 글자와 명령 응답만 보입니다. 토글이라 리셋 전까지 유지됩니다.

**에코**: 펌웨어가 받은 문자를 되돌려 보내므로 타이핑이 그대로 화면에 보이고, **백스페이스로 오타를 고칠 수 있습니다**. 터미널 프로그램(miniterm / screen / PuTTY)과 무관하게 동작합니다. 터미널 자체의 로컬 에코를 쓰고 있어 글자가 두 번 보인다면 `ECHO`로 끄세요.

> 텔레옵(`V` 명령)이 시작되면 에코는 **자동으로 꺼집니다.** 조이스틱이 초당 수백 문자를 보내는 동안 ISR 이 송신을 기다리면 수신 오버런이 나기 때문입니다.

### 서보 탐색 / 설정

| 명령 | 인자 | 설명 |
|---|---|---|
| `PING` | 없음 | ID 1~4 응답 확인 |
| `SCAN` | 없음 | ID 1~253 전체 스캔. 약 1초, 실행 중 모터 정지 |
| `ID <현재> <새>` | 현재 0~254, 새 0~253 | 서보 ID 변경 |
| `ZERO <id\|ALL>` | id 1~253 또는 `ALL` | 현재 자세를 0도로 영점 기록 |

**`ID` 주의**: 반드시 **서보를 1개만 연결한 상태**에서 실행하세요. 여러 개가 물린 채로 하면 전부 같은 ID가 됩니다. `254`는 브로드캐스트라 현재 ID를 몰라도 됩니다 — `ID 254 3`.

**`ZERO` 주의**: 서보 EEPROM에 기록되어 전원을 꺼도 유지됩니다. 실행 전에 `OFF`로 토크를 풀고 바퀴를 물리적으로 정면 정렬해야 합니다.

### 조향 제어

| 명령 | 인자 | 설명 |
|---|---|---|
| `ON` / `OFF` | 없음 | 토크 켜기 / 끄기. 끄면 손으로 돌릴 수 있음 |
| `T <a1> <a2> <a3> <a4>` | 각도(도), 최대 4개 | 조향각 직접 지정. 준 개수만큼만 전송 |
| `P` | 없음 | 현재 조향각 읽기 |
| `S <속도>` | 정수, step/s | 서보 이동 속도. `0`=최대 |
| `GATE` | 없음 | 구동 정렬 게이트 on/off **토글**. 기본 ON. 서보를 떼고 구동모터만 시험할 때 끈다 |
| `MTEST` | 없음 | 모터 자가시험 on/off **토글**. **기본 OFF**. 모터를 하나씩 정/역 2초씩 돌린다 (바퀴 띄우고). 텔레옵 전에만 |

`T`는 인자 개수만큼만 명령을 보냅니다 — `T 30`은 1번 서보에만, `T 0 30`은 1·2번에만. 각도는 `joint.c`의 서보별 `min_deg`/`max_deg`(현재 전부 ±90°)로 클램프되고, 잘리면 경고가 한 줄 나옵니다.

`T`의 인자 순서는 **서보 ID 순서**입니다. 바퀴 배치는 다음과 같습니다.

```
서보1 (LF)   서보3 (RF)
서보2 (LB)   서보4 (RB)
```

기구학 모듈 순서(FL, FR, RL, RR)와 다릅니다. 변환은 `main.c`의 `SWERVE_MODULE_SERVO[]` 한 곳에서만 합니다.

### 조향 가동범위 (바퀴별)

`joint.c`의 `joint_config[].min_deg/max_deg`가 **유일한 정본**입니다. 기구학(`swerve_fold_to_range`)이 매 제어주기 이 값을 읽어서, 목표 방향의 등가각(θ, θ±180°) 중 범위 안에 있으면서 직전 각에 가장 가까운 것을 고릅니다. 바퀴마다 값이 달라도 됩니다.

- 폭(`max - min`)이 **180° 이상**이어야 모든 방향을 낼 수 있습니다. 더 좁으면 일부 방향은 경계로 잘립니다.
- 폭이 딱 180°이면 방향마다 쓸 수 있는 각이 하나뿐이라 경계를 지날 때마다 180° 반전이 생깁니다. 반전 중에는 정렬 게이트가 구동을 멈춥니다.
- 정하는 순서: `OFF` → 바퀴 정면 정렬 → `ZERO ALL` → `ON` → `T`로 한 바퀴씩 돌려 부호(`dir`)와 간섭 각을 확인 → `min_deg/max_deg` 수정 → 재빌드.

### 기구학 주행

| 명령 | 인자 | 설명 |
|---|---|---|
| `V <vx> <vy> <ω>` | **정확히 3개** | 몸체 속도 → 4모듈 조향각+구동 duty 자동 계산 |

좌표계: **x=전진, y=좌측, ω=반시계(+)**. 단위는 m/s, m/s, rad/s.

```
V 0.1 0 0      전진
V 0 0.1 0      왼쪽 게걸음
V 0 0 1.5      제자리 반시계 회전
V 0 0 0        정지
```

동작 특성:
- **첫 구동 명령(`V` 또는 SPI)에서 텔레옵이 시작**되고 에코·로그가 꺼지며, `MTEST`가 켜져 있었다면 멈춥니다. 되돌리려면 보드 리셋. 모터 자가시험은 **기본 OFF**라 전원을 넣어도 바퀴가 스스로 돌지 않습니다.
- **50Hz 고정 제어주기**: `V`는 목표 속도만 바꾸고, IK·조향·PWM은 20ms마다 한 번씩 나갑니다(시뮬과 같은 주기). 명령이 몇 Hz로 오든 출력 주기는 같습니다.
- **구동 정렬 게이트**: 다음 중 하나면 네 바퀴의 **실제** 조향각이 목표의 10° 안에 들 때까지 구동을 0으로 둡니다.
  - 목표 조향각이 한 주기에 60° 넘게 바뀜 (큰 방향 전환, 180° 반전)
  - 구동 중 목표와 실제 조향각 차이가 60° 넘음 (조금씩 돌려서 위 조건을 피한 경우)
  - 텔레옵 후 첫 구동
  
  **1.5초** 안에 정렬되지 않으면(모래에서 정지 조향 막힘, 기구 간섭, 서보 무응답) 강제로 풀고 텔레메트리 `GATE_TIMEOUT`을 세웁니다. 서보 없이 벤치 시험할 때는 매번 1.5초씩 기다리게 되므로 `GATE`로 끄는 게 편합니다.
- **워치독**: 마지막 구동 명령 이후 500ms 동안 명령이 없으면 목표 속도를 0으로 둡니다(조향각은 유지). 조이스틱이나 Pi가 끊겨도 로버가 계속 굴러가지 않도록 하는 안전장치입니다.
- 제어주기 상태줄(`[CTRL] deg ... duty ...`)은 `LOG`가 켜져 있을 때만 5Hz로 나옵니다. 텔레옵이 시작되면 LOG는 자동으로 꺼집니다. 다시 켜면 10Hz 엔코더 로그가 한 번에 약 30ms 동안 UART 송신으로 루프를 막아 **50Hz 제어주기가 흔들립니다** (디버깅할 때만).

### Pi SPI 링크 (SPI2 슬레이브)

Pi가 SPI 마스터이고 Nucleo SPI2가 슬레이브입니다. 한 번의 전송(CS low → 144바이트 → CS high)에서 Pi는 속도 명령을 보내고 동시에 Nucleo의 텔레메트리를 받습니다. 프레임 레이아웃의 정본은 `firmware/common/spi_link.h`, Pi 쪽 구현은 `pi/common/nucleo_link.py`(`SpiLink`)입니다.

| Nucleo 핀 | 신호 | Pi 5 |
|---|---|---|
| PB12 | SPI2_NSS | CE0 (GPIO8, 핀 24) |
| PB13 | SPI2_SCK | SCLK (GPIO11, 핀 23) |
| PC2 | SPI2_MISO | MISO (GPIO9, 핀 21) |
| PC3 | SPI2_MOSI | MOSI (GPIO10, 핀 19) |
| GND | | GND |

- 모드 0, 8비트, **1MHz 권장**. Nucleo가 HSI 16MHz로 돌아서 8MHz가 절대 상한입니다.
- 항상 144바이트(프레임 v2)를 한 번의 CS 구간으로 보냅니다. 길이가 다르면 Nucleo가 그 전송을 버리고 다음 CS에서 다시 맞춥니다.
- 텔레메트리는 50Hz 제어주기마다 갱신됩니다. 명령 워치독이 있으므로 Pi는 최소 10Hz 이상, 보통 50Hz로 교환합니다.
- 텔레메트리 필드(모두 같은 50Hz 제어주기 시각 `t_ms`에 샘플). 배열은 모듈 순서 FL, FR, RL, RR입니다.
  - 구동: 적용 명령, 누적 엔코더 틱, 바퀴 속도, duty
  - 조향 서보(STS3215): 목표각, **실측 각·속도·부하·전압·온도·상태**, 모듈별 유효 비트 `servo_valid`
  - IMU(ISM330DHCX, SPI3): 자이로·가속도 원시값(센서 좌표계, ±500dps / ±4g), `IMU_VALID` 플래그
  - 상태 플래그: 워치독, 게이트 대기, 서보 읽기 실패, 조향 클램프, 명령 출처
- 서보 4개 읽기는 매 주기 약 3ms입니다. 응답 없는 서보는 0.5초 동안 건너뛰고 다시 시도합니다(타임아웃 15ms가 매 주기 반복되지 않게).
- IMU는 부팅 시 WHO_AM_I(0x6B)를 확인하고, 1초마다 다시 확인합니다. 끊겼으면 재초기화를 시도합니다.
- Pi에서 확인: `python3 pi/common/spi_monitor.py` (폴링만), `--vx 0.05` (명령 전송).
- UART `V`와 SPI 명령은 같은 목표값을 씁니다. 마지막에 온 명령이 이깁니다.
- `rover_motor.ioc`에 SPI2·SPI3가 들어가 있지만 **CubeMX가 만드는 `MX_SPI2_Init()`/`MX_SPI3_Init()`은 호출하지 않습니다.** `pi_spi.c`와 `imu_ism330.c`가 레지스터로 직접 설정합니다(USART2/3과 같은 방식).

## ★ 조립 후 반드시 할 것 (주행 전)

아래는 **로봇을 다 조립한 상태에서** 확정하는 값입니다. 코드에는 임시값이 들어 있습니다. 옵시디언 `실기 확인 목록`에도 같은 목록이 있습니다.

| # | 항목 | 코드 위치 | 현재 값 | 방법 |
|---|---|---|---|---|
| 1 | 조향 영점 | 서보 EEPROM | 미설정 | `OFF` → 네 바퀴를 자로 정면 정렬 → `ZERO ALL` → `ON` → `T 0 0 0 0` |
| 2 | 조향 방향(dir) | `joint.c` `joint_config[].dir` | 전부 +1 | `T 30`(서보1)부터 하나씩: 위에서 볼 때 반시계면 +1, 시계면 -1 |
| 3 | 조향 가동범위 | `joint.c` `min_deg/max_deg` **+ 시뮬 `sim/rl/config.py` `steer_lo_deg/steer_hi_deg`** | 전부 ±90° | `T`로 천천히 늘려 가며 구동모터·배선 간섭 각 확인. 바퀴마다 달라도 됨. 폭 180° 이상 유지. **두 곳을 같이 고친다** (시뮬은 모듈 순서 FL, FR, RL, RR) |
| 4 | 구동모터 ↔ 바퀴 | `main.c` `SWERVE_MODULE_MOTOR` | MOTOR1..4 = FL, FR, RL, RR | 바퀴 띄우고 `MTEST` → 어느 바퀴가 도는지 |
| 5 | 구동 방향 | `main.c` `MOTOR_DRIVE_SIGN` | 전부 +1 | `V 0.05 0 0`에서 뒤로 도는 바퀴의 모터 → -1 |
| 6 | 엔코더 방향 | `main.c` `ENCODER_SIGN` | 전부 +1 | 5번 후 `LOG`의 m/s가 음수인 모터 → -1 |

1~3은 **순서대로** 합니다. 영점 없이 범위를 넓히면 구동모터가 몸체에 부딪힐 수 있습니다. 4~6은 방향이 틀리면 로버가 엉뚱하게 가는 항목이라, 바퀴를 띄운 상태에서 먼저 확인합니다.

## 3. 브링업 순서

배선 후 처음 한 번 하는 작업입니다.

```
LOG                 화면 정리 (이후 완전 무음, 타이핑이 보임)
SCAN                버스에 뭐가 몇 번으로 잡혀 있나 확인
```

`SCAN` 결과가 비어 있으면 → 배선(PB10/GND), 서보 12V 전원, 보레이트를 확인하세요.

**ID 부여** (전부 ID=1로 나왔을 때. 서보 하나씩만 연결):

```
ID 254 4            연결된 서보 1개를 4번으로
                    → 분리하고 다음 서보 연결
ID 254 3
ID 254 2
ID 254 1
                    → 4개 전부 데이지체인 연결
SCAN                1·2·3·4 다 잡히는지 확인
```

높은 번호부터 부여하면 중간에 중복이 생겨도 덜 꼬입니다.

**영점 + 방향**:

```
OFF                 토크 풀기
                    → 자를 대고 바퀴 4개를 정면으로 정렬
ZERO ALL            지금 자세를 0도로 기록
ON                  토크 켜기
T 0 0 0 0           4개 다 정면 보면 성공
T 30 0 0 0          1번이 위에서 볼 때 반시계로 돌아야 정상
```

반대로 돌면 `Core/Src/joint.c`의 해당 서보 `dir`을 `-1`로 바꾸고 다시 빌드·플래시하세요. 4개 각각 확인해야 합니다. 좌우 대칭으로 장착했다면 한쪽은 `-1`이 되는 게 정상입니다.

**주행 확인**:

```
V 0.1 0 0           전진
V 0 0 0             정지
```

## 4. 자주 겪는 것

**포트는 한 번에 한 프로그램만 잡습니다.** `miniterm`이 `/dev/ttyACM0`을 열고 있으면 조이스틱 스크립트가 못 엽니다. 조이스틱 돌리기 전에 터미널을 닫으세요.

**USB는 STM32만 먹입니다.** 모터(12V)와 서보(12V)는 별도 전원입니다. USB만 꽂은 상태에서는 명령을 쳐도 프린트만 나오고 아무것도 움직이지 않습니다 — 정상입니다. 배선 검증 단계에서는 오히려 안전합니다.

**서보 VCC를 STM32에 연결하지 마세요.** 12V 외부 전원에만 직결하고, GND만 공통으로 묶습니다.

**`No debug probe detected`** → ST-Link가 USB에 안 잡힌 것입니다. `lsusb | grep 0483`으로 확인하세요. 안 보이면 케이블 문제일 가능성이 높습니다(충전 전용 케이블은 데이터선이 없어 아예 인식되지 않습니다).

**`PING`이 전부 FAIL** → 서보 전원·배선·ID를 확인하세요. 서보를 연결하지 않았다면 정상 결과입니다.

## 5. 아직 실측값이 아닌 것

다음 값들은 임시값이라 실제 측정 후 교체해야 합니다.

| 항목 | 위치 | 현재 값 |
|---|---|---|
| 모듈 장착 위치 | `main.c` `SWERVE_MODULES` | ±0.12 m (트랙·휠베이스 240mm 가정) |
| 최대 바퀴 속도 | `main.c` `SWERVE_MAX_WHEEL_MPS` | 0.378 m/s |
| 모듈↔구동모터 매핑 | `main.c` `SWERVE_MODULE_MOTOR` | 0→MOTOR1 … 3→MOTOR4 (실제 배선 미확인) |
| 모듈↔서보 매핑 | `main.c` `SWERVE_MODULE_SERVO` | FL→서보1, FR→서보3, RL→서보2, RR→서보4 (배치 확정) |
| 조향 원점·방향 | `joint.c` `joint_config[]` | offset=2048, dir=+1 (캘리브레이션 전) |
