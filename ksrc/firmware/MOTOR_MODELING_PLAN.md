# 모터·서보 모델링 계획 (sim2real)

목적: 시뮬(Isaac `sim/isaac/ksrc_rover`)이 쓰는 구동모터·조향서보 모델을 실기 측정으로 확인하고,
틀린 곳은 고치고, 측정 산포로 DR 범위를 정한다. 조립 후 실행한다.

판정 기준은 "실기 명령 시퀀스를 시뮬에 그대로 넣었을 때 속도·각도 궤적이 잡음 수준으로 겹치는가" 다.
겹치면 단순 모델로 충분하고, 특정 상황(부하·방향반전)에서만 같은 모양의 오차가 반복되면
그때 마찰·백래시 항 추가나 구동기 신경망(actuator net)을 검토한다.

> **2026-10-12 결정: 구동은 펌웨어 FF + 속도 PI 로 간다 (개루프는 버릴 예정).**
> 지금 펌웨어(개루프)와 시뮬이 어긋나는 핵심: 시뮬은 정책이 바퀴 **목표 속도**를 주고 DCMotor 가
> 그 속도를 따라가므로, 전압·모터 개체차 DR 이 토크·최고속만 바꾸고 **무부하 속도는 명령 그대로**다.
> 실기 개루프는 duty 고정이라 배터리 85% 면 85% 속도, 모터마다 ±5% 가 그대로 좌우 속도 차이가 된다.
> PI 가 엔코더로 속도를 맞추면 실기가 시뮬 쪽 동작에 가까워진다.
> **실기에서 아직 확정한 값은 없다** (전부 데이터시트·추정, 무부하 77.8 rpm 한 번 잰 것 뿐).
> 그래서 PI·FF 의 시뮬 반영과 최종 teacher 학습은 모터 연결 → 아래 §0 측정 → 펌웨어 PI 구조 확정 **뒤에** 한다.
> 그 전의 RL 학습은 보상·구조 탐색용이다.

### 시뮬 모델 (`assets/rover_cfg.py`, `utils/contract.py`, `rover_env_cfg.py DR2`)

| | 모델 | 값 (출처) |
|---|---|---|
| 구동 | `DCMotorCfg`: τ = clip(d·(ω* − ω), 토크-속도 직선) | 정지토크 1.96 N·m, 무부하 7.96 rad/s (데이터시트), d = 0.246 (= 정지토크/무부하속도, 10-12 에 0.20 에서 올림), 반사관성 armature 1.5e-3 kg·m² (추정) |
| 조향 | `ImplicitActuatorCfg`: 위치 PD | kp 12, kd 0.30, 최고속 5.45 rad/s, 토크 1.912 N·m (STS3215 데이터시트) |
| DR | 전압 0.85–1.05, 모터 편차 ±5%, d 0.8–1.2배, armature 1e-3–3e-3, 서보 속도 0.7–1.0, 서보 강성 0.8–1.2, 행동 지연 0–1, 관측 지연 1–2 스텝 | 추정 |

개루프 전압 구동의 물리식은 τ = τ_stall·(duty − ω/ω_noload) = (τ_stall/ω_noload)·(duty·ω_noload − ω) 이다.
역기전력 때문에 "이득 τ_stall/ω_noload = 0.246 의 속도 P 루프"와 같은 모양이라 시뮬 구조는 맞고, d 도 0.246 으로 맞췄다.
단 이 등가는 (1) effort_limit 가 정지토크 이상일 때 (지금 1.96 = 정지토크, OK), (2) 목표속도 = duty·ω0(전압) 일 때만 성립한다.
(2) 가 지금 시뮬에서 깨져 있다 (위 결정 박스).
수치는 전부 데이터시트·추정이고, 아래 항목은 시뮬에 아예 없다.

| 시뮬에 없는 것 | 영향 |
|---|---|
| 구동 저속 데드밴드·정지 마찰 (기어 131:1) | 작은 duty 에서 안 돌다가 갑자기 돎. Res8 의 미세 보정이 이 영역 |
| MDD3A duty→전압 비선형 | duty 와 속도가 비례하지 않을 수 있음 |
| 배터리 전압 강하 (부하·잔량) | 같은 duty 에 속도가 달라짐 |
| 조향 데드밴드·백래시 | 작은 각도 명령 무시, 방향 반전 시 지연 |
| 조향 부하 의존 속도 (지면 마찰) | 정지 상태 조향이 느려짐 |

3. **고속 캡처 모드** (10-12 추가). 모터 시정수는 시뮬 값으로 J/D = 0.00156/0.246 ≈ 6 ms 라
   50 Hz 텔레메트리(20 ms)로는 계단 응답이 한 샘플 안에 끝나 D2(시정수→armature)·L2(지연)를 못 잰다.
   펌웨어가 1 kHz 로 엔코더 누적 틱·duty 를 RAM 에 1–2 s (4바퀴 × 2000 샘플 ≈ 32 KB) 기록하고 UART 로 덤프한다.
   속도는 틱 위치 곡선을 맞춰서 구한다 (1 ms 당 최고속에서도 ~10 틱). 조향은 `STEP` 이 이미 ~0.7 ms 로 읽는다.
4. SPI 명령 추가 시기: sysid(바퀴별 duty·각도) 와 고속 캡처는 측정 전, PI on/off·이득과 텔레메트리 확장(PI 적분·FF duty,
   프레임 길이/버전 변경 → `pi/common/nucleo_link.py`·테스트 같이)은 PI 구현 때, 바퀴별 주행 명령(조향 4 + m/s 4)은
   Res8 로 확정될 때만 (Res3 면 지금 vx,vy,ω 명령 그대로).
5. 엔코더는 16비트 타이머인 채널이 있다(`Encoder_IsWide`). 펌웨어가 int32 로 누적하는지 확인하고,
   아니면 긴 실험에서 넘침을 처리한다.

## 3. 실험 — 구동 모터

모든 실험은 4개 모터 각각, 정·역 방향 모두. 배터리 전압을 실험 시작·끝에 기록한다.

| ID | 조건 | 프로파일 | 얻는 값 |
|---|---|---|---|
| D1 | 바퀴 띄움 (무부하) | duty 0 → ±799 를 50 단계 계단, 단계마다 1.5 s 유지 | 정상상태 ω(duty) 곡선: 무부하 속도, **기동 데드밴드**, MDD3A 비선형, 모터 개체차 |
| D2 | 바퀴 띄움 | duty 계단 0→200, 0→400, 0→799, 799→0, +400→−400 | 1차 시정수 τ_m → 반사관성 J = τ_m · d, 지연 |
| D3 | 바퀴 띄움 | duty 를 천천히 0 근처에서 ±(0→150) 삼각파 3회 | 정지 마찰 vs 운동 마찰 (기동 duty 와 정지 duty 차이 = 히스테리시스) |
| D4 | 지면, 직진·옆걸음 | 차체 속도 계단 (기존 SPI 명령 v 0.05/0.1/0.2/0.3) | 하중 상태 속도 저하, D1 대비 차이 |
| D5 | 지면, 경사 또는 견인 (용수철저울로 끌기) | 일정 duty 에서 하중 단계적 증가 | 토크-속도 직선 기울기 → d, 정지토크 확인 |
| D6 | 배터리 만충 / 중간 / 저전압 | D1 일부 (duty 200/400/799) 반복 | 전압 배율 범위 → `voltage_scale` DR |

주의: D5 에서 모터를 오래 정지(stall) 시키지 말 것. 정지토크 측정은 1 s 이내, 전류·온도 확인.

## 6. 맞추기와 시뮬 반영

관성과 토크는 무부하 계단 응답만으로는 분리가 안 된다 ((J_wheel + J_arm)·ω̇ = τ_s·u − D·ω − τ_f 에서
가속이 작은 게 관성이 커서인지 토크가 작아서인지 모름). 순서대로 따로 구한다:
D1 정상상태 속도 → ω0·데드밴드 (관성 무관) / D5 하중 기울기 → D / D2 시정수 τ_m = J/D → J.
DR 은 물리 관계를 지킨다: 전압은 정지토크·무부하속도를 같이 (D 불변), 감속기 손실·효율은 D 를 따로.

| 측정값 | 시뮬 반영 위치 |
|---|---|
| D1 무부하 속도, D5 정지토크 | `contract.WHEEL_MAX_RAD_S`, `DRIVE_EFFORT_NM` |
| D5 토크-속도 기울기 | `rover_cfg.py` drive `damping` (지금 0.20, 이론 0.246) |
| D2 시정수 | drive `armature` (= τ_m · d). 지금 1.5e-3 은 추정 |
| D1·D3 데드밴드·마찰 | 새로 추가: 관절 마찰(`friction`) 또는 데드밴드를 넣은 커스텀 액추에이터 |
| D1 비선형 | 비선형이 크면 액션 → duty 변환에 측정 곡선의 역함수(펌웨어) 또는 같은 곡선(시뮬) |
| D1·D6 개체차·전압 | DR `motor_spread`, `voltage_scale` 범위를 측정 산포로 |
| S1 | steering `stiffness`, `damping`, `STEER_MAX_RAD_S` |
| S2·S3 | 새로 추가: 조향 데드밴드·백래시 (커스텀 액추에이터 또는 행동 단계에서 목표각 양자화) |
| S4 | DR `servo_rate_scale` |
| L1–L3 | DR `action_delay`, `obs_delay` |

절차:
1. 실기 로그의 명령 시퀀스(duty·각도)를 시뮬 단일 바퀴/단일 모듈 테스트에 그대로 재생하는 스크립트
   (`sim/isaac/ksrc_rover/scripts/actuator_replay.py`, 새로 만듦).
2. 파라미터를 최소제곱으로 맞춘다 (속도·각도 궤적 RMSE).
3. 맞춘 값을 기본값으로, 모터 4개·배터리 상태 산포를 DR 범위로.
4. 지면 실험(D4·S4·S5)은 로버 전체 시뮬로 재생해 차체 속도까지 겹쳐 본다.

## 7. 검증

- 맞추기에 안 쓴 시퀀스(다른 계단 크기, 임의 스윕)로 겹쳐 보기.
- 합격 기준 (초안): 바퀴 속도 RMSE < 정상상태 속도의 10%, 조향각 RMSE < 2°, 응답 지연 차이 < 1 스텝(20 ms).
- 실패 시 잔차 모양을 본다. 부하·방향반전 때만 반복되는 오차 → 마찰/백래시 항 보강, 그래도 안 되면 actuator net.
- 마지막으로 IK 주행(정책 없이)을 실기·시뮬에서 같은 명령으로 돌려 차체 속도·yaw 를 비교한다.

## 8. 펌웨어 속도 PI (2026-10-13 설계·구현, 벤치 미확인)

**코드**: `common/wheel_pi.{h,c}` (순수 C, 호스트 테스트 `common/tests/test_wheel_pi.c`), `main.c` `Swerve_Control` 에서 호출.
터미널 `WPI ON/OFF/SET`, 벤치 캡처 `WCAP`, 노트북 `sysid_uart.py pi`. **기본 ON** (`WHEEL_PI_DEFAULT_ON 1`, 10-14 벤치·지면 확인: 계단 41–51 ms, 지면 0.15 m/s 정확, 바퀴 간 duty 7 %).
시뮬: MuJoCo/가짜 펌웨어는 `sim/libksrc_common.so` 로 **같은 C** 를 부른다 (`sim/ksrc_common.py WheelPi`).
Isaac(GPU 배치)은 torch 로 옮기고 `WheelPi` 와 같은 입력열로 비교 검증할 것 (미구현).

**구조** (20 ms, 현 50 Hz 제어주기 그대로):

```
r_m  += (w* − r_m)·dt/(τm + dt)              기준 모델 τm = 40 ms (= 실측 기계 시정수)
e     = r_m − w_meas                          w_meas = 이번 주기 엔코더 차분 (20 ms 창, 1틱 0.0375 rad/s)
duty  = w*/0.0097 + sgn(w*)·5 [+ sgn(w*)·40 바퀴가 멈춰 있으면] + 82.5·e + I
I    += 2062·e·dt   (출력이 e 방향으로 포화면 안 쌓음),  |I| ≤ 200
|w*| < 0.001 → duty 0 (브레이크) + 상태 초기화.  정렬 게이트 보류 중에도 초기화.
```

| 결정 | 이유 (설계 시뮬, 실측 플랜트: 1차 τ 40 ms + Stribeck 마찰 + 정지마찰 47 duty, 1틱 양자화) |
|---|---|
| 50 Hz (현 루프) | 200 Hz(5 ms 타이머 인터럽트) 와 비교해 부하 처짐 0.41 vs 0.36 rad/s 로 이득이 작고, duty 떨림은 3배. 인터럽트·CubeMX 변경 없음 |
| 기준 모델 τm 40 ms | 없으면 FF + P 가 겹쳐 계단 오버슈트 36%. 넣으면 0.5% (PI 는 FF 가 만든 궤적과의 차이만 고침) |
| kp = 20·τ/k, ki = kp/τ | 극점-영점 상쇄, 루프 대역 20 rad/s. 30 이면 떨림↑·오버슈트 1.8%, 15 면 부하 회복 170 ms |
| 기동 킥 40 duty | 정지마찰(기동 35–52). 없으면 0→0.3 rad/s 기동 59 ms, 있으면 28 ms |
| I 상한 200 | 20° 경사 바퀴당 ~80 + 전압 −15% 중속 ~60. 1 s 막혔다 풀릴 때 튐 3.2 rad/s (목표 2) |
| 저역통과 없음 | 20 ms 창 1틱 × kp = 3 duty 떨림. 필터는 지연만 늘림 |

설계 결과 (공칭): 0→2 rad/s 90% 37 ms·오버슈트 0.5%, 정상오차 0, 전압 −15%·부하 80 duty 에서도 정상오차 0,
부하 계단 처짐 0.41 rad/s 를 130 ms 에 회복. τ 30–50 ms·기울기 ×0.85–1.05·정지마찰 35–55 에서 오버슈트 ≤ 5.5%.
개루프(현행)는 0.3 rad/s(14 mm/s) 명령에 정지마찰로 **아예 안 돌고**, 전압 −15% 면 2 rad/s 에서 0.39 rad/s 모자람.
한계: 0.145 rad/s(7 mm/s) 아래는 마찰 때문에 연속 회전 불가 → 평균은 맞지만 섰다 돌았다 함 (0.1 rad/s 에서 정지 15%).

**남은 것**
1. 벤치 (바퀴 띄움): `WPI` 로 이득 확인 → `python3 pi/common/sysid_uart.py pi` → 위 설계값과 비교 (90% ~37 ms, 오버슈트 <3%, 정상오차 <0.02).
2. 지면: `WPI ON` 후 `V 0.05 0 0` / `V 0.1 0 0` 직진, `CTRL ON` 으로 duty 확인. 경사·모래에서 I 포화 여부.
3. `WHEEL_PI_DEFAULT_ON 1`.
4. Isaac 액션 항에 같은 PI (torch, 물리 4스텝마다 = 20 ms) + 구동 모델을 duty 입력으로 (`τ = 0.246·(duty/799·ω0 − ω)` 그대로)
   + 정지·Stribeck 마찰 (관절 마찰 또는 액션 항에서 토크로). 그 뒤 teacher 이어학습.
5. 바퀴가 헛돌 때 PI 가 duty 를 줄여 견인력도 줄어든다 (목표 속도까지만) — 시뮬에서 확인.
6. 바퀴별 SPI 명령 (조향각 4 + 바퀴 속도 m/s 4). 지금 SPI 는 차체 속도만이라 Res8 출력을 못 넣는다.

   모델 검증에서 FAIL 난 시험 종류.  REF 표류 FAIL 이면 배터리 상태 확인 후 다시.

**6. 나머지 서보 (각 ~4분, 개체차)** — `steer --servo 2 --reps 2`, 3, 4.  서보1 과 가속도·최고속·지연이 같은지.

**7. (시간 남으면) S4 지면 조향, D6 배터리** — 바퀴 내리고 `steer --servo 1 --tag ground` 를 띄운 것과 비교 (#14).
   배터리 반쯤 썼을 때 `drive --tag batt_mid --reps 2` 로 D1 비교 (#8).

**8. 결과 정리** — 각 디렉터리 `summary.json`·`report.txt` 를 Claude 에게 넘긴다 → §0 표 채우고, 시뮬 반영값(ω0, d, armature, 데드밴드,
   서보 가속·최고속·지연, DR 범위) 과 펌웨어 PI 설계(§8) 로 넘어간다.  #4(D5 하중), #10(PI), #11(전압판 라벨), L1(SPI) 은 그 뒤.

신뢰도 기준: 각 report.txt 끝의 "종합: FAIL 0" 이면 그 값은 반복·조건·모델 검증을 통과한 것.  반복성 FAIL 만 있으면 `--reps 10` 으로 다시,
모델 검증 FAIL 은 측정 문제가 아니라 모델에 빠진 항이 있다는 뜻 (그 시험 종류를 보고 판단).


## 11. Student 관측 = 실기와 같은 계산 (2026-10-13)

teacher 는 시뮬 참값(관절 속도, 참 중력)을 보지만, student 는 실기에서 Pi 가 받는 값과 **같은 식**으로 만든 관측만 본다.
식은 한 곳에 두고 양쪽이 쓴다: Isaac `utils/sensors_torch.py` (torch) ↔ Pi `pi/common/sensor_fusion.py` (numpy),
같은 입력열에 같은 출력인지 `sim/rl/test_actuators.py` 가 비교한다.

| 관측 | 실기 (텔레메트리 → Pi) | 시뮬 (student 그룹, `mdp/dr.py` `*_src`) |
|---|---|---|
| 바퀴 속도 | 펌웨어 엔코더 틱 20 ms 차분 `wheel_mps` / 반경 | 관절 각 → 틱(8384/rev) → 20 ms 차분. 잡음 없음 (양자화가 곧 오차) |
| 조향각 | 서보 위치 레지스터 `steer_meas_rad` (4096 격자, 서보 축 = 링크 놀음 안 보임) | (관절 각 − 서보 오프셋 DR) → 4096 격자 |
| 조향 속도 | 서보 속도 레지스터 `steer_speed` step/s | 관절 속도 → step/s 격자 + 잡음 |
| 중력 방향 | IMU **20 ms 평균**(펌웨어 `Imu_Poll`/`Imu_TakeMean`, `imu_n`) → 보완 필터 | 20 ms 평균 IMU (자세 변화 / dt, 속도 차분 + g) → 같은 보완 필터 |

보완 필터: 자이로로 예측 `g ← g − dt·(ω×g)`, 가속도 크기가 9.81 ± 1.5 m/s² 일 때만 `−f/|f|` 쪽으로 dt/0.5 s 만큼 당김.
리셋(부팅) 뒤 첫 정상 가속도 샘플로 초기화. 자이로 바이어스는 부팅 정지 평균으로 뺀다 (`GyroBias`).

**IMU 를 주기 평균으로 바꾼 이유**: 시뮬 거친 지형에서 50 Hz 순간 자이로를 적분하면 차체 진동이 겹쳐(aliasing) 평균 24° 틀어지고,
보완 필터를 써도 평균 4°·p95 15° (PhysX 가속도가 튐: 가속도계 단독 평균 14°). 주기 평균이면 평균 0.8°·p95 2.3°
(`scripts/student_obs_check.py`, 64 env, DR 2단계, 관측 지연 포함). MuJoCo 거친 지형 0.46°.
실기 펌웨어도 그래서 순간값 1개 대신 ODR 208 Hz 샘플을 주기마다 평균해 보낸다 (미검증: `imu_n` 이 3–4 인지 확인).

남은 것: 실기 로그로 필터 확인 (정지·주행 중 중력 추정이 서보·지형과 맞는지), Pi 쪽 관측 조립기 (텔레메트리 → student 입력, 순서·이력은 Isaac 과 같게).

**재점검 (같은 날, `scripts/imu_sanity.py`)**: Isaac IMU 센서 자체는 맞다 (평지 정지 가속도 (0,0,9.81), 자이로 = 몸체 각속도).
하지만 거친 지형에서는 **서 있기만 해도** 가속도가 순간 최대 62 m/s² 튄다 (평균 흔들림 0.55 m/s², 가속도계 단독 기울기 p95 13°).
바퀴가 지형 메시 위에서 떠는 PhysX 접촉 떨림으로 보이며, 평지 주행에선 순간값 ≈ 20 ms 평균이다.
→ 위 "24°/4°" 는 PhysX 거친 지형 특유의 값이고 (24° 에는 일부러 넣은 자이로 바이어스 표류도 섞임), 실기 진동 크기는 모른다.
펌웨어 IMU 주기 평균은 해가 없으니 유지. **실기 측정일**에 IMU 208 Hz 고속 캡처(정지·요철 주행)와 정지 기울기 시험(0/10/20°)으로
필터 시정수·게이트와 아래 DR 범위를 다시 정한다. Pi–STM 통신 주기(L1)도 같은 날.

**중력 관측 오차 DR** (`rover_env_cfg.py GRAV_ERR`, `mdp/dr.py randomize_gravity_error`): 시뮬 필터가 실기보다 깨끗할 수 있으므로
student 중력 관측에 에피소드마다 고정 기울기 0–3° (수평축 무작위) + 표류 0–0.3°/s, 합 ≤ 5° 를 넣는다. 실측 후 조정.
teacher 민감도 평가용으로 `--set GRAV_ERR_POLICY=True` 면 policy 그룹에도 들어간다.
